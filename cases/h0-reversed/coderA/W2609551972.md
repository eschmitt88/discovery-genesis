## Reasoning
Even reversed, idea-first is not close: there is no proposition here. Accretion, heard last, is also clearly wrong — this is not an aggregation of prior results but an actively engineered tool release. The real question is means-first vs. problem-first, and the v1.1 rule is decisive: the capabilities added (CASSIS, SANDPUMA, extended RODEO, DIAMOND) were each first cited within ~1-3 years of this paper and are external methods newly integrated, not the authors' own long-reused sub-algorithm applied to a new target. That is the textbook means-first tell as written in the codebook's "Tell for means-first" bullet.

## Alternative reading
One could argue antiSMASH itself (the authors' own platform, self-cited across 2011/2013/2015 versions) is being "reused on a new target" (this year's set of gene clusters), which would push toward problem-first under the serial-reuse rule. But that rule is meant for a stable method applied to a new empirical target (next gene, next species); here the tool's own internal *methods* are what changed release-to-release, which is a different pattern — capability accretion within the same artifact, still means-first in spirit.

## Notes for the codebook
Software/tool-update papers with self-citation of the tool's own version history are an edge case the v1.1 self-citation rule doesn't cleanly address: self-citing "our own tool v1-3" isn't the same as self-citing "our own assay applied four times to four targets." Worth a worked example distinguishing platform self-citation (still means-first if the *methods inside* are new) from target-reuse self-citation (problem-first).
