## Reasoning
This is a textbook `formalisation` move: the codebook's own example set ("an ontology, an equation, a metric") matches exactly what this paper does — takes the informal, label-only notion of "business capability" used across the process-modelling literature and gives it a formal, RDF-encoded representation. Per v1.1 rule 6, a framework paper with no primary dataset (here, evaluation via ontological consistency checks and interviews, not a study of capability outcomes) defaults to `idea-first` when its stated structure organizes the design, which fits: the meta-model is proposed first and the two evaluations are then run against it.

## Alternative reading
means-first is a plausible alternative if RDF itself, or the specific meta-model-authoring tooling, is treated as a "new instrument" the paper introduces — but RDF long predates this paper and is used as a representation language, not a novel capability the authors built. I weighted idea-first higher because the paper's own contribution is explicitly the conceptual meta-model, not a new tool for building such models.

## Notes for the codebook
Straightforward application of both the `formalisation` label and the v1.1 framework-paper rule; no real ambiguity here. Worth noting this is also a decent example distinguishing `formalisation` from `new-theory-or-formalism` enabler — the move and the enabler point at the same artefact here, which the codebook doesn't say is disallowed but is worth flagging as a pattern (formalisation papers will often have `new-theory-or-formalism` as enabler almost tautologically).
