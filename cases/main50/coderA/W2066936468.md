## Reasoning
The abstract is explicit that the "improvement" is a combination of two named, non-original strategies (solution-sharing, elitist learning) applied atop basic PSO — a within-field recombination of existing algorithmic components (codebook §2 transfer-vs-recombination boundary: same field, so recombination not transfer). The target problem itself (DED with wind power, valve-point effects, spinning reserve) is also heavily pre-established per the reference list, so the paper is applying/refining an established optimization platform on a specific problem instance rather than introducing a genuinely new capability — problem-first. gap-filling:next-target is listed second because the specific problem instance (adding both wind-reserve constraints and valve-point nonsmoothness together) is itself a next-step extension of the cited 2006-2009 wind-dispatch PSO papers; removing it would lose that this is also incrementally extending the target problem, not just recombining algorithm parts.

## Alternative reading
means-first is the alternative if "solution-sharing strategy" (uncited as existing, i.e. possibly introduced here) is in fact a genuinely new capability rather than an established technique — abstract-only evidence can't confirm whether this specific strategy has prior citations of its own.

## Notes for the codebook
This is a good test of the recombination vs gap-filling:next-target boundary when both apply at once (combining known algorithm parts AND extending to a marginally harder problem instance) — the rule "second label only if removing it would make the card false" was genuinely useful here to justify keeping both rather than picking one.
